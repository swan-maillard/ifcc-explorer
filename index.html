IFCC, a C compiler

A compiler for a subset of C that six of us wrote at INSA Lyon in 2024. It turns C into its own intermediate representation, optimises it and writes x86-64 or RISC-V assembly. My part was the control flow: switch and case, break and continue, and return inside loops.

      What you're looking at

      A compiler doesn't go from C to assembly in one jump. IFCC first turns each function into basic blocks: short runs of instructions that always execute together, top to bottom. Each block ends with a jump, a test that picks one of two blocks, a switch or a return. Drawn as boxes and arrows, that's the control-flow graph in the middle.

      The IR (intermediate representation) uses $ names for the variables you declared and # names for temporary values. You see it after the compiler's four optimisation passes: constants are worked out ahead of time, temporaries nobody reads are dropped, empty blocks are skipped and blocks nobody can reach are removed. That's why some lines of C leave nothing behind.

      Each backend then writes every block under the same label, and every IR instruction as a few lines of assembly that load from and store to the stack. Hover or select anything to see where it came from and what it became. The links come from the compiler itself: a small exporter I added notes which C statement was being compiled when each IR instruction was created.

      Run mode steps through the IR with a small interpreter written in TypeScript, and each variable sits in the same stack slot as in the real assembly. For every program here, its exit code matches the program built by GCC and the ones IFCC built for both backends. The tests check that.
